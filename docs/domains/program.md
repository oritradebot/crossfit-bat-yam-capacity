## 1. מבנה הנתונים

התוכנית יושבת ב-`public/app.html` כשמונה מתודות, `programWeek1()` .. `programWeek8()`
(שורות ~2056-2406), שמוזרקות ב-`applyProgram()` דרך `overlay(weekIdx, this.programWeekN())`.

```js
programWeek8() {
  return {
    0: {                                    // אינדקס יום: 0=ראשון .. 6=שבת
      lift:   { movement:'Back Squat', planned:'...' },
      metcon: { name:'AMRAP 12:00', scheme:'AMRAP 12:00',
                score:'Rounds + reps', resultMode:'rounds', note:'...' },
      metcon2:{ ... },                      // אופציונלי — ניקוד שני באותו יום
      extras: [['כותרת','תוכן'], ['','']],  // ראה מלכודת #1
      alt: {                                // רק ימי ראשון — אימון אינדורנס
        metcon: {...}, metcon2: {...}, extras: [['',''],['','']]
      }
    },
    1: { ... }
  };
}
```

**מבלוק 2 (07/09/2026) — שלד + דמו:**
- `programWeekN()` הן התוכנית של **הבלוק הנוכחי**. שבוע שעוד לא הוטמע מחזיר `this.blankWeek()` —
  שבוע ריק **במפורש** (כל שדה `''`, כולל `alt` ביום 0), כדי שמכשיר שעדיין נושא את התוכנית של
  הבלוק הקודם יימחק ל-COMING SOON. הטמעה = להחליף את הגוף `{ return this.blankWeek(); }` בתוכן המלא.
- `demoWeek1()..demoWeek8()` = תוכנית בלוק 1 מילה-במילה, **לדמו בלבד** (`/demo`; הרישומים
  לדוגמה ב-`DEMO_LOG` נכתבו מול האימונים האלה). `applyProgram` בוחר לפי `this.IS_DEMO`.
  אל תערוך אותן; אפשר למחוק אותן (ואת `DEMO_MAPS`) כשהדמו יורד.
- מפות הקונפיג (`PER_SET_LIFT` וחברותיה) מתחילות ריקות בבלוק החדש; הערכים של בלוק 1 יושבים
  ב-`DEMO_MAPS` ונטענים רק בדמו. `CAPACITESTS` (מיקומי המבחנים) עדיין מצביעים על שבוע 1/8 של
  בלוק 1 — לעדכן עם הטמעת שבוע 1 של בלוק 2 (ולהוסיף מתג דמו אם הדמו עוד חי).

**בריף יומי (מבלוק 2, אורי 07/09):** כל יום מקבל `brief: '...'` — הטקסט מהכותרת "Brief" בצילום,
מילה במילה. מוצג בכרטיס משלו בראש היום מעל LIFT (לשני הסשנים). זה טקסט תוכנית (לא רישום): לא
בחתימת הסנכרון, נמחק ע"י שבוע ריק, נערך במצב העריכה של המנהל.

**מבחן שבועי (מבלוק 2):** ב-`CAPACITESTS_BLOCK2` (app.html, בלוק ה-BlockRecap) רשומה עם
`weekly: { di, src }` במקום `base`/`retest` — נמדדת באותו יום בכל שבוע. "לפני" = השבוע הראשון
שנמדד, "אחרי" = האחרון, ושורת צ׳יפים W1..W8 במסך המבחנים. מבחני בלוק 1 ב-`CAPACITESTS_BLOCK1`

`tools/` אם יופקו כרטיסים מגיבוי.

**`alt` = אימון האינדורנס של יום ראשון.** רק **אחד** מהשניים נספר ונרשם ביום —
הנעילה ההדדית כבר ממומשת (`otherDone` ב-`renderVals`, שומרים ב-`saveDay`/`toggleDone`).

## 2. ⭐ כללי `resultMode` — לב השיטה

| בתוכנית כתוב | `resultMode` | הערה שנוספת |
|---|---|---|
| **AMRAP** (כל סוג) | `'rounds'` | `"הזינו כמה סבבים (+חזרות) הושלמו"` |
| **For Time** — כולל עם time cap | `'time'` | הקאפ **לא** משנה את זה |
| **סכום מוצהר** ("total cleans/cals/DU/T2B") | `'amount'` | גם אם הכותרת "For Time" |
| **ניקוד זוגי/קבוצתי מסוכם** | `'amount'` | |

**המקרה המבלבל:** AMRAP שבסקרינשוט כתוב עליו *"total reps"* → **נשאר `'rounds'`**.
מוסיפים הערת גישור (`"סבב = 30 חזרות"` / `"כל מדרגה בסולם נספרת כסבב"`) ומיידעים את אורי.
תקדימים: W4 ראשון, W6 חמישי.

**החריג היחיד ל-`for time`:** W2 שישי הומר ל-`rounds` — כי זה היה *סטים בתוך קאפ פתוח*,
כלומר AMRAP בתחפושת. קאפ רגיל על for-time נשאר `time` (W3 שלישי, W4 שלישי, W6 שלישי/שישי/שבת).

**שבוע 1 של בלוק 2 (07/09):** AMRAP עם "total reps" → `rounds` (הכלל); אימון תחנות קבוצתי **בלי ניקוד כתוב** →
`amount` על סך הפאוור קלינים (האפליקציה דורשת תוצאה למטקון כדי להשלים יום; אורי אישר, אפשר לשנות);
חתירה במרווחים בלי ניקוד (METCON-B) → `time` על זמן החתירה הכולל. כשהניקוד המוצהר הוא סך של תנועה
אחת מתוך התיבות (סך ה-HSPU / הפאוור קלינים / ה-Wallwalks) — `PER_MOVE_SCORE` משקף את התיבה לניקוד.

**שני ניקודים ביום אחד** (W8 שלישי, 03/09): הפיס הראשון ב-`metcon`, השני ב-`metcon2`,
וה-`lift` מועבר **ריק במפורש** — `{ movement:'', planned:'' }` — אחרת טקסט ישן שורד
אצל משתמשים קיימים (מלכודת #1). `canComplete` ידרוש את שניהם.

## 3. מפות קונפיג — למלא בכל הטמעה

כולן מפתחות `'weekIdx_dayIdx'` (0-מבוסס), נפתרות בזמן רינדור — **בלי שדות state**.

| מפה | שורה | מה |
|---|---|---|
| `PER_SET_LIFT` | ~2011 | משקל לכל סט: `'7_0': 8` = 8 תיבות |
| `PER_MOVE_METCON` | 2024 | תוצאה לכל תנועה במטקון |
| `PER_MOVE_BOXES` | 2029 | רשימת תיבות מותאמת (כשלא 1:1 עם התנועות) |
| `PER_MOVE_SCORE` | 2034 | ניקוד הלוח משקף תיבה מסוימת — **מספר התיבה = האינדקס המקורי של התנועה** (או המיקום ברשימת `PER_MOVE_BOXES` אם יש); מ-08/09 לא חובה רשימת תיבות מותאמת, אבל כדאי לרשום אותה בכל יום כזה |
| `METCON_AMOUNT_LABEL` | 2043 | תווית לימי `amount` (במקום מ׳/קל׳ הגנרי) |
| `METCON_RX_NOTE` | 2048 | הסבר מה RX אומר ביום הזה |
| `TIME_SPLITS` | ~2290 | **זמן לכל מקצה** (08/09): `'0_0': { 'alt.metcon2': ['Row 1600','Row 1000','Row 800'] }` — תיבת XX:XX לכל מקצה, הסך נכתב ל-`log.time` אוטומטית |
| `PER_MOVE_OFF` | ~2290 | **כל יום עם שורות רמה** (אורי 08/09): `'0_0': ['metcon']` — רמה + ציון בלבד, בלי תיבות לתנועות. W1: ראשון, שני, רביעי, שישי |
| `ROUND_REPS` | ~2300 | **סבב שגודלו תלוי ברמה** (08/09): `'0_5': { 'metcon': { '1': 50, '2': 64, '3': 80 } }` — סבבים + חזרות בנפרד, הסך = סבבים × גודל הסבב של הרמה + חזרות |

### כמה תיבות ב-`PER_SET_LIFT`?

- ספירת הסטים **כפי שכתובה** בתוכנית
- EMOM סינגלים → ספירת הדקות (`'0_5'`, `'2_5'` = 10)
- בנייה לכבד בלי מספר קבוע → **8 תיבות פתוחות** (`'0_0'`, `'5_5'`)
- ימים לסירוגין → רק הסטים של תנועת המוט (`'3_6'` = 4 מתוך 8, `'4_3'` = 5 מתוך 10)
- **אין משקל מוט לרשום** (ג׳ימנסטיקס EMOM, DB, בנץ׳, צוות/נשיאה) → **אין רשומה בכלל**

### הרמה היא שלב 1 של ההזנה (08/09, אורי)

- **הפילים נגזרים מטקסט המטקון:** `planLevels` קורא את שורות `L1 = …` / `Level 2 — …` של ה-`note` (אותן שורות
  שמוצגות כטבלה) ומציע **רק** את הרמות הכתובות — בבלוק 2 L1-L3, אין L4. לכן בהטמעה שורות הרמה חייבות להישאר
  בתבנית `L1 = …` (או `Level 1 = …`), אחרת לא יהיו פילים.
- **נעילה:** ביום עם רמות, תיבות התנועות והציון נעולים עד שנבחרה רמה ("🔒 בחרו רמה בשלב 1"), ומספרי השלבים
  זזים: תיבות = שלב 2, ציון = שלב 3 (או "שלב 2 · הזמן שסיימתם" כשאין תיבות). יום בלי שורות רמה — בלי פילים ובלי נעילה.
- **⭐ יום עם שורות רמה = רמה + ציון בלבד, בלי תיבות לתנועות** (`PER_MOVE_OFF`). אורי 08/09: *"ביום כמו שני לא
  צריך את שלושת הקוביות אלא רק באיזו רמה ומה תוצאת הזמן"*, ואז על ראשון ורביעי: *"כן תסיר גם … זה קלאסי מהמקרים
  שהתכוונתי אליהם"*. הרמה כבר אומרת מה בוצע (משקל, חזרות, מרחק ריצה). W1: ראשון (סך HSPU), שני (זמן), רביעי (סך
  Wallwalks), שישי (סבבים + חזרות, סך לפי `ROUND_REPS`). **בכל הטמעה: יום עם שורות רמה → רשומה ב-`PER_MOVE_OFF`.**
- **חריג שנשאר עם תיבות — W1 שלישי (תחנות), אורי 08/09:** *"גם רמה וגם קוביה למספר חזרות לכל תרגיל"* + *"קוביה
  של תוצאה — מספר החזרות הכוללת של כל הסיבובים ב-POWER CLEAN"*. ההזנה: רמה ← ספירה לכל תחנה **לסבב** (`Bike (cals /
  round)` וכו׳) ← תיבת תוצאה נפרדת "סך הפאוור קלינים מכל הסבבים" (`METCON_AMOUNT_LABEL`). **בלי `PER_MOVE_SCORE`** —
  הסך מוקלד, לא נגזר מתיבה. תווית `METCON_AMOUNT_LABEL` גוברת על "Score / תוצאה" גם ביום עם תיבות (08/09).
- **ממוצע התיבות** ("ממוצע התנועות: 12") מוצג רק כשה-`score` של המטקון הוא ממוצע ("Avg reps per minute", יום הפיילוט
  של W4 בבלוק 1) — לא לספירות של תחנות ולא למשקלים.
- **יום בלי שורות רמה (W1 חמישי):** אין פילים ואין נעילה, אבל **כן** תיבת משקל לכל תנועה שיש לה משקל — ורק להן
  (`'0_4': ['Wall balls (kg)','Single arm DB (kg)']`, בלי תיבה לקפיצה לארגז). כשכל התיבות `(kg)` הבלוק נקרא
  "שלב 1 · משקלי העבודה", הנעילה אומרת "מלאו את המשקלים", ואין ממוצע (ממוצע קילוגרמים חסר משמעות).
- הקיצור הישן "התוצאה הראשונה מאמצת את הרמה הקודמת" הוסר — הרמה נבחרת במפורש (רמז "בפעם הקודמת L2" נשאר).

### `ROUND_REPS` — סבב שגודלו תלוי ברמה (08/09 — אורי: *"תשכלל מספר חזרות לכל סט לפי הרמה … 3 סיבובים מלאים + 20 חזרות → לפי הרמה לסכום את כמות החזרות הכוללת"*)

- **מתי:** AMRAP במצב `rounds` שהניקוד המוצהר שלו הוא סך חזרות, והסבב שונה בין הרמות (שישי W1: 300/400/500 מ׳
  + BFB + T2B לפי רמה, 10 מ׳ ריצה = חזרה). הערך = חזרות לסבב לכל רמה, מחושב משורות הרמה; טווח (L1: 45-50) →
  המספר של אורי (50).
- **מה המתאמן עושה:** שלב 1 רמה, שלב 2 סבבים מלאים + חזרות מהסבב האחרון (שדות `rounds` / `reps` הרגילים).
  מתחת: "סבב ברמה L2 = 64 חזרות …" ואחרי ההזנה "✓ סך החזרות לפי L2: 3 × 64 + 20 = 212 חזרות".
- **הסך מחושב, לא נשמר** (`roundTotal(key, sess, base)`): `resultTextAt` מוסיף "= 212 חזרות" בתמצית הבלוק,
  ב"בפעם הקודמת", ב-CSV, ו-`logSummaryText(day, key, alt)` בכרטיסי השיתוף ובדגלי השיא. שינוי רמה מעדכן את הסך.
  `resultMode` נשאר `rounds` (חוק ברזל 7) ו-`metconScore` לא השתנה — בלי דירוג ב-v3 זה לא משנה.

### זמן: XX:XX אוטומטי, ו-`TIME_SPLITS` למקצים (08/09 — אורי: *"בכל מקום שיש ריצה/חתירה או כל דבר לפי מטרים… הזנת התוצאה תהיה אוטומטית XX:XX"*)

- **כל שדה זמן** (תוצאת `time` ותיבות המקצים) מקבל ספרות בלבד ממקלדת מספרים ומתעצב מימין תוך כדי הקלדה:
  1 → 0:01, 12 → 0:12, 123 → 1:23, 1230 → 12:30 (`fmtTime`, `timeEl`). נשמר כמו שמוצג, עד 99:59; אין נקודתיים להקליד.
- **`TIME_SPLITS`** — מטקון במצב `time` שהציון שלו הוא סכום של כמה מאמצי מרחק (חתירה 1600/1000/800) מקבל תיבת
  זמן לכל מקצה (`log.t1..tN`), והסך נכתב ל-`log.time` רק כשכל התיבות מלאות (`onSplitEdit`) — אין שדה זמן נפרד.
  הערך במפה = רשימת תוויות התיבות, לפי סדר המקצים. תיבה ריקה נמחקת (כמו סטים של LIFT); שדות `tN` שורדים
  נרמול (`normalizeDay`) וסנכרון (`cleanLog` ב-boot.js שומר כל מפתח לא-ריק).
- **מתי להוסיף:** "Row/Run X · Y · Z" עם ניקוד זמן כולל → רשומה. מרחק בתוך AMRAP/סבבים (ריצה 200 מ׳ בין תחנות,
  300-500 מ׳ לפי רמה בשישי) → **לא** — הציון שם הוא סבבים/זמן כולל ממילא; וכשהרמה קובעת את המרחק אין תיבת
  מטרים בכלל (אורי 08/09: *"אין צורך להשאיר תיבת מטרים כי בשישי יש רמות שכוללות גם את מרחק הריצה"*).
  טקסט האימון לא משתנה בגלל המפה (ההערה "הזינו את זמן החתירה הכולל" נשארה נכונה — הסך נכתב).

## 4. מלכודות

1. **`applyProgram` דורס רק אינדקסים שקיימים במקור.** אם ליום חדש יש פחות `extras`
   מהישן — הוסף `['','']` מפורש, אחרת נשאר אצל המשתמש extra ישן ותקוע.
   אותו דבר ל-`lift` ריק.
2. **חייבים לעלות `PROGRAM_VERSION`** (שורה 1997) בכל הטמעה. בלעדיו מכשירים קיימים
   לעולם לא יקבלו את השבוע החדש.
3. **להטמיע לפני יום ראשון של אותו שבוע.** תוכן מגיע למשתמשים קיימים **רק** דרך
   הטמעה בקוד. הטמעה מאחרת = כל הרוסטר רואה מסך "COMING SOON" בלי שדות הזנה
   ולא יכול לרשום. זה קרה בפועל 04-10/08.
4. **גרסת האפליקציה לא זזה בהטמעה.** מעלים **רק** `PROGRAM_VERSION`.
   `BUILD` + `version.json` זזים רק כשאורי נוקב במספר. ראה `release.md`.
