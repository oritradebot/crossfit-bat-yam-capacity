## 3. כפתור איפוס בלוק (פאנל האדמין)

- **מיקום:** ליד 💾 גיבוי / ♻️ שחזור.
- **היקף** (אורי: "למחוק את כל הנתונים באפליקציה, בלי לגעת בתשתית"): כל שורות `states` + `board` **כולל של אורי**; `shared_program`: `weeks = null`, `block_recap = null`, `announcement = null`. **נשארים:** `auth.users`, `profiles` (שם/מין/תאריך לידה/דגלים), `announcement_log`, כל הטבלאות והפוליסיז.
- **נעילות** (הכפתור מושבת אלא אם שתיהן מתקיימות):
  1. מצב תחזוקה דולק — הפאנל קורא את `version.json` (no-store).
  2. גיבוי טרי **מהמכשיר הזה** בתוך 60 הדקות האחרונות — לפי `cfby_backup_last` (`BK_KEY`) שהפאנל כבר מתחזק.
- **אישור:** הכפתור מציג "יימחקו נתונים של N מתאמנים" (N = משתמשים עם שורת `states` או `board`) ואורי מקליד את N. מספר שגוי = לא קורה כלום.
- **ביצוע:** פונקציית שרת אחת, `admin_reset_block(p_label text)`, SECURITY DEFINER, בודקת `is_admin()`, **טרנזקציה אחת**:
  1. `insert into block_archive` — כל שורת `states` ו-`board` יחד עם `profiles.name` באותו רגע.
  2. `delete from states`, `delete from board`.
  3. `update shared_program set weeks=null, block_recap=null, announcement=null where id=1`.
  4. מחזירה `{ archived_states, archived_board, deleted_states, deleted_board }` והפאנל מציג את המספרים ומרענן.
- **חוזר על עצמו:** נלחץ פעמיים בבלוק — נתוני בלוק 1 (תווית `block-1`), ואז נתוני הבדיקה רגע לפני הפתיחה (תווית `block-2-tests`). תווית חופשית, ברירת מחדל לפי הבלוק.
- **בלי מחיקות מהלקוח.** הכל דרך ה-RPC כדי שארכיון ומחיקה יהיו אטומיים.
- **הגנות בלחיצה (נבנו מעבר לאפיון):** שתי הנעילות נבדקות שוב ברגע הלחיצה; הכפתור מסרב כשיש דחיפה באוויר או נתונים לא מסונכרנים (`pushBusy || unsynced()`), כי upsert שנוחת אחרי ה-delete היה יוצר מחדש את השורה של אורי עם נתוני בלוק 1; אחרי הצלחה `dropLocalCopy()` ואז reload.
- הארכיון שומר גם את שורת `shared_program` (kind `program`), כך שהתוכנית, ההודעה והגייט של הבלוק שנסגר נשמרים.

### טבלת הארכיון

```sql
create table if not exists public.block_archive (
  id          bigserial primary key,
  label       text not null,                       -- 'block-1', 'block-2-tests', ...
  kind        text not null check (kind in ('states','board','program')),
  user_id     uuid,                                -- null לשורת התוכנית; בלי FK: הארכיון שורד מחיקת משתמש
  name        text not null default '',            -- שם המתאמן ברגע הארכוב
  data        jsonb not null,                      -- ה-tracker המלא / שורת הלוח המלאה
  archived_at timestamptz not null default now()
);
-- RLS: קריאה/כתיבה ל-admin בלבד (is_admin()).
```

הכל כבר ב-`supabase/schema.sql` (הקובץ כולו ניתן להרצה חוזרת). **הורץ על המסד החי 06/09 בלילה (אורי).** אומת אנונימית: ה-RPC מחזיר 401 (קיים, אסור ל-anon) מול 404 לפונקציה שלא קיימת; הטבלה מחזירה 200. הפאנל עדיין מזהה פונקציה חסרה ומסביר, למקרה של מסד אחר.

## 4. שאריות במכשירים (כלל "השורה נעלמה")

**נבנה אחרת מהאפיון המקורי (מזהה בלוק), לטובה.** במקום לחתום כל tracker במספר בלוק, המכשיר זוכר האם הוא כבר *פגש* את השורה שלו בענן:

- `boot.js` שומר `cfby_srvrow_v1 = "1"` בכל boot שבו השרת החזיר שורה, ובכל דחיפה מלאה שהצליחה.
- ב-`main()`, בענף "השרת ענה ואין שורה": `rowGone = אין שורה && יש tracker מקומי && הסימן קיים && הפרופיל נקרא בהצלחה (לא _err ולא _missing)`.
  - `rowGone` → העותק המקומי **נזרק** דרך `dropLocalCopy()` (מראות בזיכרון, טיימרים של דחיפה, המפתחות של tracker/dts/dirty/board/הסימן), זריעה מחדש כמו משתמש חדש, ואם הייתה חותמת dirty מוצגת פעם אחת ההודעה: *"נמצאו רישומים מהבלוק הקודם שלא סונכרנו, הם לא נכללים בבלוק החדש"* (הפופאפ של ההודעות, בלי קונפטי, כפתור "הבנתי").
  - אין שורה ובלי סימן → משתמש חדש שהדחיפות הראשונות שלו נכשלו: שומרים מקומי ודוחפים, **בדיוק כמו היום**.
  - יש שורה → מיזוג רגיל, בלי שינוי. לכן לפני האיפוס ההתנהגות זהה להיום.
- למה לא מזהה בלוק: לא תלוי בשעון המכשיר, לא דורש חתימה על כל כתיבה של האפליקציה (ה-normalize של האפליקציה היה מוחק שדה זר), ומכסה גם מחיקה של משתמש בודד מהפאנל.
- למה נדרש פרופיל מאומת: תחת RLS קריאה אנונימית (סשן מת) מחזירה "ריק" בלי שגיאה. `fetchProfile` מסמן עכשיו `_missing` כשהשורה לא חזרה. בלי ההוכחה הזאת, סשן מת היה נראה כמו איפוס.
- אחרי איפוס מהפאנל, המכשיר של אורי עצמו זורק את העותק שלו לפני ה-reload (`dropLocalCopy()`), כדי שדחיפת סגירה לא תחזיר את בלוק 1 לענן.

> ⚠️ **סתירה לתיעוד מסשן מקביל:** ב-`docs/domains/backup.md` (הכרעות 06/09, סשן הגיבויים) רשום שרעיון "אפוק בלוק" (השרת מסמן בלוק פעיל, המכשיר זורק עותק מקומי ישן) הוא "לא רלוונטי". באותו ערב, בסשן האפיון הזה, אורי ענה לשאלה ישירה "מה קורה לרישומי בלוק 1 שלא סונכרנו" ובחר **"להשליך + הודעה חד-פעמית"**, והסתירה הוצגה לו במפורש לפני שאמר "תתחיל". הכלל כאן צד-לקוח בלבד, בלי סימון בשרת.

## 7. שיאים שעוברים בין בלוקים (07/09, לילה) — נבנה

**הכרעת אורי (07/09 ערב, מבטלת את "בלוק 2 דף חלק" מאותו בוקר):** השיאים בלבד — לא המבחנים — שורדים את מחיקת נתוני הבלוק, עם רישום מאיזה בלוק הגיעו. שיא מבלוק 1 נשאר ומסומן **BLOCK I** עד שנשבר באותו תרגיל בבלוק 2. בנוסף: "BLOCK II" (רומי) בקצה העליון של הדף.

| רכיב | מה בדיוק |
|---|---|
| **מספר הבלוק** | קבוע אחד ב-`app.html`, `BLOCK_NUM` (ליד `startDate`), מועלה בכל בלוק. מוצג כפס דק בראש הכותרת הדביקה (`{{ blockLabel }}` = `'BLOCK ' + roman(n)`), נחשף לפאנל כ-`window.cfbyBlockNum`, ומופיע גם בכותרת כרטיסי השיתוף מהאפליקציה (לא בכרטיס הסיכום ב-`design/`). |
| **הפנקס** | `profiles.prs jsonb` — הטבלה היחידה עם נתוני מתאמן שהאיפוס לא נוגע בה. צורה: `{ v:1, lifts:{ <normName>:{ move, best, reps, week, block } }, flags:[ { key, move, res, week, block } ] }`. בלי ימים ובלי תאריכים (הלוח של הבלוק נמחק איתו). `lifts` = המשקל הכבד ביותר ב-LIFT לכל תרגיל, `flags` = ימים שסומנו 🏆. המבחנים לא בפנקס — הם של הבלוק. |
| **מי כותב** | **רק הפאנל**, בתוך `wipeRun` (`carryPRs`), רגע לפני `admin_reset_block`: שולף `profiles(id,prs)` + `states(user_id,tracker)`, לכל מתאמן מחשב `window.cfbyCollectPRs(weeks, block)` וממזג עם הפנקס הקיים ב-`window.cfbyMergePRs` — שתי הפונקציות הן קוד השיאים של האפליקציה עצמה (מקור אמת אחד; `packLedger`/`mergePRs` ב-`app.html`). כתיבה אחת (`upsert` על profiles, רק ל-ids שכבר יש להם פרופיל). **כל כשל עוצר לפני המחיקה.** המיזוג אידמפוטנטי — הרצה חוזרת של האיפוס לא משכפלת. |
| **תיבת 📌 בדיאלוג האיפוס** | מסומנת כברירת מחדל; התווית קובעת את מספר הבלוק שמוטבע (`block-1` → 1 → "BLOCK I"), ותווית שמכילה `test` מבטלת את הסימון לבד (אורי יכול לדרוס ידנית). לא מסומנת → השיאים לא עוברים ("השיאים לא הועברו" בהודעה). |
